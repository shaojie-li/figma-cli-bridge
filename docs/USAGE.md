# 与 Codex 和 Figma 一起设计

默认 document 模式复用目标文件自己的主题。下文涉及 Luigi 色板、命名、字体、图标和组件合同的规则适用于显式选用的 Luigi 示例。

适用于独立 figma-local-bridge 工程。当前已验证的是桌面 Figma 中的 Button Light 样本、设计读写、规范检查和恢复通道；插件不是内置聊天机器人，也不是已完成的全组件自动生成器。

## 平时怎么使用

1. 在 Figma 桌面版打开目标文件并运行「Figma CLI Bridge」。目前精确允许的文件是 CLI Bridge · Sandbox。正常设计期间保留插件运行，Figma 可以在后台。
2. 在 Codex 直接描述任务。Codex 负责检查本机服务、必要时启动/构建、绑定目标、读写设计和验收；通常不需要你打开终端、输入配对码或手动点击连接。
3. 在 Figma 看真实变量、组件和实例；也可直接看 Codex 返回的原生导出图片。这里是可编辑设计，不是把图片贴进 Figma。
4. 修改意见继续在 Codex 说。可以先在 Figma 选中对象，再说“调整我选中的按钮”；Codex 先调用 `design.selection` 获取真实选区，再回读这些 ID。选区为空或多个对象意图不明时再定位，不能猜对象。
5. 任务完成可以关闭插件。再次工作时运行一次插件；短暂断线与服务重启后的可信绑定自动恢复。不需要为每条设计命令重启。

小窗口默认只有状态、暂停和设置，264 × 48 px，上下各 12 px。可拖到不影响操作的角落；本版本没有自动定位窗口的能力。正常就绪不显示说明文字。设置按需展开，配对码隐藏。异常详情只在必要时显示，并随内容增加窗口高度。

## 你说什么，我做什么

| 你在 Codex 说 | Codex 的工作 | 你在 Figma 做什么 |
|---|---|---|
| “我想做一套温暖、偏阅读感的组件” | 确定产品气质、平台与范围，读取已有规范，给出具体字体/颜色/密度方向 | 查看后续样本 |
| “参考这张图的排版，不要照搬配色” | 提取排版关系，保持已确定的颜色来源和 Phosphor | 可提供参考链接或图片，不需要手动生成节点 |
| “先只做 Button，不改现有版本” | 在独立命名空间和样例区域制作，避免改动被旧组件共享的 Token | 对比两个版本 |
| “我选中的按钮太挤，左右间距加大” | 读取选区、组件与变量来源，判断应改实例还是主组件，并按规范精确修改 | 选中目标即可 |
| “我自己改了字号，按这个继续” | 重新读取实际画布和差异，保护你的修改；不能拿旧快照覆盖 | 可以正常手工编辑 |
| “这些可以了，补齐所有规定状态” | 按组件合同生成/修正状态和属性，检查绑定、尺寸、边界和 PNG | 验收结果，而不是逐个手工拼状态 |

执行期间尽量不同时手动修改同一对象。发现 fingerprint 或 seal 变化会停下回读，不替用户抹掉修改。

## 新风格的推荐开始方式

可以直接复制这段话到 Codex，再改成你的需求：

> 在 figma-local-bridge 中，给阅读类 Web 产品做一套温暖、安静、偏编辑排版的组件风格。先只做 Button，保留 Phosphor，先出一个方向和少量样例，再补齐约定状态。放在当前 Sandbox 的独立区域，保留现有蓝色 Button。颜色优先沿用现有色库，字号和布局遵循项目规范。

有参考图、目标平台、品牌色或希望包含的组件时直接附上；缺少非关键细节由 Codex 按项目规范判断，不要求填写整张需求表。品牌方向真正存在冲突时才需要你选择。

顺序：产品目标与设计方向 → 新风格 profile/Token 映射 → 小样 → 基础变量验收 → 组件状态与属性验收 → 实际画面审查 → 后续产品页面。

“换风格”可以调整字体、密度、圆角、色彩、边框和视觉层级；不改变可读性、对齐、语义、状态完整性等质量要求。Phosphor 保持统一。新风格使用独立变量/组件归属，避免改一个共享主色就连带改变现有基线。

## 当前能力边界

- 已完成的生成操作 `button.complete` 是现有 Button 的固定迁移，不能用它假装能一键生成任意风格。`luigi-compact` 目前只是规则候选，不是可直接切换的成品库。
- 新风格或新组件由 Codex 在具体任务中补齐对应 Token、生成操作和验证，再通过插件执行；你仍用自然语言交流，不需要写 Plugin API 代码。
- 毛玻璃工单后台是一个独立画板样本，不是新的组件库。`design.compose` 可配置根层环境渐变、面板透明度、描边与原生背景模糊；`design.patch` 的 `fillOpacity` 可用最新 fingerprint 精确调整 Frame 的单个已绑定纯色填充，不解除颜色绑定。具体例子见 `design/glass-dashboard.mjs`。
- 目前只放行已有 Sandbox。要使用另一个文件，需要明确目标并更新精确绑定/文件守卫；仅改成相似名字不能获得写入权限。新文件按 `产品 · 用途 · 平台` 命名。
- 普通插件需要打开的 Figma 文件和运行中的插件；不能在 Figma 退出、插件关闭或电脑睡眠后继续设计。
- Figma 静态状态和图片验收不等于 Web/iOS 交互、键盘、读屏和动效已经实现。

## 自动处理与确实需要你操作的情况

- 短暂离线：自动退避重连，无弹窗催促；本机服务由 Codex 检查。
- 首次绑定：Codex 指定准确目标并保存信任记录。之后只恢复唯一、身份匹配的文档；不会自动信任同名新文件或在多个会话间乱选。
- 结果未知任务：连接可以恢复，写入不会盲目重放；Codex 查询回执和画布后按恢复协议继续。
- 有效且活跃的本机配对：临近到期自动续期。闲置过期或凭据更换：Codex 检查服务、更新构建后先探测，不立即要求你复制配对码。
- 插件被关闭/执行端持续无响应：才需要你在 Figma 运行一次插件。
- 错误文件、真正权限限制或无法推断的目标：指出具体原因和最短操作。
- 暂停按钮只暂停连接，不保证撤销已交给 Figma 的任务；正在执行时不要把它当作撤销按钮。继续连接后由 Codex 核对未确认任务。

## 代理使用的命令

用户通常不需要执行以下命令；它们用于独立工程恢复：

```sh
npm start
npm run build
node src/cli.mjs status
node src/cli.mjs bind
```

`design.selection` 为只读请求，参数为空；根据返回的节点 ID 再调用 `design.read`。任务状态和恢复方法见 Skill 的 `references/setup.md`。
