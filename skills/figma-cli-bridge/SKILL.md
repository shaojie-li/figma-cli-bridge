# Figma CLI Bridge

当前对话负责设计判断、调用本地命令和看图验收。用户只需描述目标，例如“给独立开发者做一个桌面发布确认页，主操作是确认发布，复用现有 Button”。沿用已授权的文件、风格和范围。所有 Figma 操作只走本地 CLI 和桌面开发插件。禁止调用 Figma 官方 MCP，包括 Starter 的建会话、只读查询、写入和导出；不要调用官方服务探测套餐或额度。连接失败先用本地诊断恢复；缺少操作时说明具体限制，完成本地可验证的部分，不把切换官方连接列为后备选项。这个 Skill 也不启用 Figma AI、Computer Use 或另一个 Codex CLI 会话。

## 建立工作环境

1. 用本 Skill 的绝对目录定位 `scripts/bootstrap.py`。从任何工作目录都可运行 `python3 <Skill目录>/scripts/bootstrap.py doctor`。以返回的 `bridge` 为后续命令工作目录；用户指定的位置可用 `--bridge <目录>`。忽略聊天当前所在的其他仓库。
2. 写设计稿时直接运行 `prepare` 完成诊断和可恢复的启动操作；单纯查询用 `doctor`。它能从 Skill 自带的校验源码包恢复、安装锁定依赖、启动 loopback 服务并用本机凭据构建插件。两个命令用 JSON 的 state 区分状态，只有 ready 返回 0。按 [初始化与恢复](references/setup.md) 处理其余情况，保留用户原工程、配对和队列。
3. 首次或更换目标时核对文件身份。只在唯一已授权 Sandbox 绑定。已有就绪会话直接工作；插件需在目标文件保持运行，Figma 可留在后台。
4. 新用户从空白 Sandbox 开始时，按[四套配色与画板切换](references/theme.md#四套配色与画板切换)预检并执行 `design.template`，创建四个颜色集合、29 个 Layout 尺度和五档文字样式。新画板按集合 ID 和角色取色，完成后用 `design.theme` 接入画板切换。已有设计系统沿用目标文件的主题（`document`）。先按[自定义主题模板](references/theme.md)盘点变量、共享文字样式、图标组件和业务组件。用户明确选用 Luigi 示例时才读 bridge 中的设计规范并启用 `luigi-default`。

## 设计和执行

- 扩展已有产品页时，先按[同页设计的一致性](references/theme.md#同页设计的一致性)回读基准画板；将同一基准用于页面、组件和弹窗的生成与验收。
- 从用户目标确定平台、主操作、真实内容、信息层级、关键状态和目标宽度。可推断的细节自行决定；目标文件、授权范围或关键产品决策有歧义时才询问。
- 先用 `design.selection` 定位实际页面，再用 `design.read` 取得真实变量、共享文字样式、主组件、属性和对象 ID。缺少资源时说明需要的角色，由用户在 Figma 创建、指定或授权采用示例。产品稿复用通过验收的实例；新风格和第三方 Kit 先做隔离样本再采用。不要伪造组件、用普通 Frame 冒充实例或 detach。
- 默认每个独立的新设计任务在已绑定的 `CLI Bridge · Sandbox` 新建一个 Figma Page，按 `90 · Sandbox · 任务主题` 命名。盘点来源组件后，用 `design.page` 建页并记录返回的 pageId；同一任务的多张画板、其他尺寸和后续迭代均复用它。用户指定已有页面、当前页或选区时直接在指定位置处理。只读评估不建页。建页失败先核对原因，需改用其他页时由用户指定。
- 新画板用 `design.compose`，它支持嵌套 Auto Layout、可编辑文字和真实组件实例。先 dry-run 再以新请求 ID 应用同一份计划。修改已有图层用 `design.patch` 和最新 fingerprint。所有路径的参数与操作示例见 [调用与验收](references/design.md)。只用执行端声明的动作；需求超出能力时指出缺哪种操作，按已授权范围补适配或交付可验证的子集，不能把子集声称为整稿。
- 颜色、文字、图标与组件按用户要求和文档中已有的对象 ID 复用；保留原命名、字体、变量集合与模式。读写和审计默认用 document。Luigi 的色表、Phosphor、固定字号、间距及组件合同仅用于显式选用的示例。
- 同一画板需要暖色、暗色等可切换方案时，使用本地 `design.theme` 绑定画板和渐变色标，切换后分别导出原生 PNG。参数见[调用与验收](references/design.md#画板主题与渐变)。
- 每次只派发一个写任务。非终态先取原任务；断线和超时按初始化文档恢复。保持同一份请求、文档身份和 ID。

## 验收后交付

回读新增或修改的节点与组件集，核对目标内容、真实绑定、实例、状态合同和布局，再运行 `design.audit`。用 `design.export` 获取原生 PNG 并实际打开查看。检查字重与层级、边距与光学对齐、清晰主操作、长文案、溢出和焦点环。用户要求多个宽度/状态时分别验证。修正可处理的问题再回读。汇报文件/页/画板名和真实节点 ID、预览、已通过与仍未验证的项目。历史样本、dry-run、结构审计或示意 PNG 均不能单独当作真实写入和视觉验收。
